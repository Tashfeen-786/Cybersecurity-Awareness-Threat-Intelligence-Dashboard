## Data flow, step by step

1. **Synthetic/public defensive threat data** — `generate_threat_data.py`
   builds 2,200 threat records + 60 synthetic vulnerabilities using only
   documentation-range IPs (RFC 5737/3849), example/invalid domains
   (RFC 2606), synthetic hashes and fictional CVE-format IDs.
2. **Data ingestion** — `init_database()` loads the CSVs into the normalized
   SQLite schema.
3. **Normalization** — timestamps, categories, severities, statuses and
   indicator values are normalized; every indicator is re-validated.
4. **IOC validation/extraction** — syntax-level validation for IPv4, IPv6,
   domain, URL, MD5/SHA-1/SHA-256 and CVE IDs.
5. **Threat enrichment** — local context: first/last seen, categories,
   sources, related alerts, cluster indicators, ATT&CK, notes.
6. **Risk + confidence engine** — two separate, explainable 0-100 scores.
7. **Correlation engine** — campaign clusters, shared-indicator clusters and
   weak time/category links.
8. **Three parallel consumers** — the threat database, the alert engine
   (with duplicate correlation), and the ATT&CK mapping service.
9. **REST API** — FastAPI serves analytics + analyst workflow endpoints with
   authentication, RBAC, rate limiting and audit logging; it also serves the
   static frontend.
10. **SOC dashboard → analyst** — triage, investigation, documentation,
    decisions.
11. **Parallel awareness track** — 15 learning modules, 36-question quiz,
    server-side scoring, personalized recommendations, and the executive
    summary combining technical and human risk views.

## Technology stack (and why)

| Layer | Choice | Why |
|---|---|---|
| Backend | **FastAPI** (Python) | Modern, automatic OpenAPI docs, pydantic validation — beginner-friendly but industry-real |
| Database | **SQLite** | Zero-config local database; schema is PostgreSQL-compatible for growth |
| Analytics | **Pandas** | Industry-standard aggregation for the dashboard charts |
| Frontend | **HTML + CSS + vanilla JavaScript** | Matches the PDF's project structure (section 39); runs offline with no build tools — easy on Windows |
| Charts | **Chart.js (bundled locally)** | Works fully offline (no CDN); professional SOC-style visuals |
| Testing | **pytest + FastAPI TestClient** | Industry-standard automated testing |

The PDF offers three stack options (A: Flask/HTML, B: React/FastAPI,
C: advanced microservices). This implementation is a deliberate **hybrid of
A and B**: the modern FastAPI backend from Option B with the simple,
no-build frontend from Option A — the best balance of "beginner-friendly,
easy to run on Windows" and "industry-oriented". A React/Recharts port is
listed in future improvements.

## Design principles

1. **Defensive only** — no attack functionality, no outbound connections.
2. **Offline by design** — everything works with zero internet access.
3. **Explainable analytics** — every score returns a factor breakdown.
4. **Honest intelligence** — risk ≠ confidence; correlation ≠ attribution;
   IOC match ≠ compromise; unmapped ATT&CK stays unmapped.
5. **Security built in** — auth, RBAC, rate limiting, sanitization, audit.
